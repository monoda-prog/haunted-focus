# Haunted Focus

A local-first productivity app that turns focused work into a glowing haunted house. Built with JavaScript and Vite; no account, backend, tracking, or external fonts.

## Run

Requires Node.js 22.22.2+ (22.x), 24.15+ (24.x), or 26+. Tested with Node.js 24.22.1.

```sh
npm ci
npm run dev
```

Open the local URL printed by Vite. For a production bundle:

```sh
npm run check
npm run preview
```

`npm run build` creates `dist/`, suitable for static hosting. No site has been deployed by this change. For subdirectory hosting use `npm run build -- --base=/haunted-focus/`.

## Features

- 25-minute focus and 5-minute break timers with start, pause, resume, reset, and explicit mode switching.
- A completed focus session lights a window and offers a break. Breaks never start automatically.
- Local task list with add, complete, undo completion, and delete controls.
- Daily focus minutes/session counts, plus current task completion totals.
- Keyboard controls, visible focus, meaningful status announcements, system and explicit reduced-motion support.
- Browser-local persistence and JSON backup export. Data is not sent to a server.

## Time and storage rules

The running timer uses a wall-clock deadline. It continues across background tabs and reloads, and settles once when the app is next active. Device clock changes affect it. A full focus session counts once at its deadline, not when the tab wakes up. Partial sessions and breaks do not count. Statistics use the current local timezone; changing zones can change which records belong to today. The illustration has seven windows, but session counts are never capped.

Reset and mode switching ask before discarding an active or paused session. Task deletion is immediate. Completed tasks may be toggled back to incomplete without creating reward records.

Browser storage is best-effort, not permanent. Clearing site data removes progress; use Settings → Export data for a JSON backup (import is not currently supported). Corrupt saved data is not overwritten; the session uses temporary state with a warning. Storage/quota failure likewise shows a warning. Modern browsers use Web Locks to allow only one editing tab. Close the original tab and reload the other to edit there; browsers without Web Locks stop editing after an external storage update, but cannot fully prevent simultaneous first writes. No OS notifications or sound are requested.

## Verification

```sh
npm test          # timer, storage validation, tasks, local-day boundaries
npm run test:e2e # Chromium UI checks (install browser first)
npm run check    # unit tests + production build
```

For browser tests, run `npx playwright install chromium` once, or set `CHROMIUM_PATH` to an installed Chromium executable. The browser suite starts its own local development server.
